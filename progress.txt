## Codebase Patterns
- Gerenciador de pacotes e `uv`. Todo comando roda por `uv run`. Nunca pip/poetry.
- Config so em `backend/config.py`. Nenhum modulo le `os.environ` direto.
- Invariante de dados vive no schema (NOT NULL, UNIQUE, CHECK, trigger), nao na aplicacao.
- Teste de banco em dois niveis: SQLite in-memory (fixture `session`) e Postgres via Alembic
  (fixture `pg_engine`, marker `integration`, pula em 3s se o banco nao responde).
- `from __future__ import annotations` no topo de todo modulo (mypy strict + Python 3.12).
- Docstrings e comentarios em portugues; identificadores em ingles.
- Migrations sao aditivas. Nunca editar revisao ja aplicada.
- Scripts do Ralph leem prd.json via Python, nao jq (jq nao esta instalado nesta maquina).
- Congelar `datetime.now()` em teste sob mypy strict: o `now(cls, tz=None)` tem que devolver
  `cls(...)`, nao `datetime(...)` - senao o `override` quebra por tipo de retorno incompativel.
- `monkeypatch.setattr(modulo, "time", ...)` quebra o mypy strict quando "time" e so um
  `import time` no topo do modulo (nao reexportado). Importe `time` no proprio teste e mocke
  `time.sleep` ali - mesmo objeto de modulo, mesmo efeito, sem acessar atributo nao reexportado.
- Coluna NOT NULL nova em tabela com dados existentes: `server_default` na migration de criacao,
  depois `op.alter_column(..., server_default=None)` para nao deixar o default preso no schema -
  o default de verdade fica so no `mapped_column(default=...)` do lado Python.
- Registro de implementacoes plugaveis (estrategias, backends, etc): `dict[str, Callable[[], T]]`
  chaveado pelo nome de config + funcao fabrica que levanta `ValueError` pra nome desconhecido no
  boot (construcao do objeto que usa o registro), nunca em runtime no meio de um ciclo. Mesma
  familia do `_load_x` de dependencia pesada, mas pra escolha entre implementacoes, nao ausencia
  de pacote.
- Duplicar um campo em duas tabelas (em vez de JOIN) e valido quando cada tabela serve uma consulta
  diferente que precisa funcionar mesmo sem a outra existir (ex: FK nullable do lado que faltaria).
  Documentar o motivo no comentario da coluna - sem isso parece dado redundante por descuido.
- `MT5Terminal` e um Protocol estrutural: metodo novo no Protocol exige atualizar TODO FakeTerminal
  usado como `terminal=` em teste, senao o mypy strict rejeita a injecao (exceto onde o dublê ja
  tem `# type: ignore` deliberado).
- Nenhum percentual cruza a fronteira do risk_manager. Toda quantidade que entra em validate_order
  (exposicao, risco por trade, perdas) e valor monetario na moeda da conta; o risk_manager converte
  os tetos configurados em % para monetario internamente (equity * pct/100). Nome do parametro
  deixa a unidade explicita (current_exposure_monetary, trade_monetary_risk), nunca so
  current_exposure. Bug real: comparar percentual (~1-5) com teto monetario (~milhares) fazia o
  teto nunca disparar (historia 28).
- Estado monotonico (ex: pico de equity) nao precisa de tabela dedicada: reaproveitar o audit_log
  gravando um evento a cada novo maximo: o evento mais recente ja e o valor vigente (ORDER BY id
  DESC LIMIT 1). Bloqueio com reset manual segue sempre o mesmo par de eventos trigger/reset do
  kill switch (historia 18) - ver backend/execution/drawdown_guard.py (historia 29).
- Adicionar valor a um enum nativo do Postgres exige migration propria (ALTER TYPE ... ADD VALUE
  IF NOT EXISTS), nunca editar a migration que criou o tipo. SQLite (testes de unidade) deriva o
  CHECK do enum Python atual, entao um valor novo passa despercebido lá mesmo sem migration - so
  o Postgres real expõe a ausencia. ADD VALUE funciona dentro da transacao padrao do Alembic
  (Postgres 12+), desde que o valor novo nao seja usado na mesma transacao que o adiciona.
- `mapped_column(default=...)` so se aplica no INSERT/flush, nunca na construcao do objeto Python
  em memoria. `Instrument(symbol="X")` sem `session.add()`/commit tem `volume_step is None` (nao o
  default do model) se usado na hora por uma funcao pura - passe todos os campos usados
  explicitamente no construtor em teste unitario que nao persiste o objeto.
- Arredondamento de volume/lote para baixo no passo do broker: `math.floor(bruto/step + 1e-9) *
  step`. O epsilon absorve erro de ponto flutuante da divisao (6.999999999997 tem que virar 7, nao
  6) sem arredondar para cima de verdade nunca.
- Sincronizar metadado de broker (min_volume, volume_step, volume_max, contract_size) e "todos os
  campos ou nenhum" no mesmo ponto (`_get_or_create_instrument`). Adicionar um campo novo a
  SymbolInfo sem incluir na comparacao/atualizacao ali deixa o registro local desatualizado em
  silencio - so aparece quando o valor errado entra numa conta de risco (historia 31).
- Coluna `TimestampTZ` lida de volta do banco em teste unitario (SQLite) vem naive; em Postgres
  vem aware. Subtrair direto de `datetime.now(UTC)` estoura `TypeError` so no SQLite. Normalize com
  `momento if momento.tzinfo is not None else momento.replace(tzinfo=UTC)` (padrao ja existente em
  `outcome_recorder._utc`) sempre que o valor for usado em aritmetica Python, nao so em filtro
  `WHERE` (que roda no SQL e nao sofre o problema).

[2026-08-04] História 1 — Scaffold
- Ambiente de dev: Windows 10, sem Docker, `python` do PATH é o stub da Windows Store.
  Python 3.12.13 instalado via `uv python install 3.12`. Todo comando roda por `uv run`.
- `MetaTrader5` é win32-only. Resolvido com marker `sys_platform == 'win32'` no pyproject,
  para o CI em Ubuntu não quebrar na resolução de dependências.
- `transformers`+`torch` movidos para o extra `nlp`: ~2GB não pertence ao caminho crítico do CI.
- O fail-closed do trading mode ficou como propriedade derivada (`effective_trading_mode`), não
  como validador do campo. Motivo: um validador que rejeita valor inválido derruba o processo no
  boot; a propriedade derivada degrada para demo, que é o comportamento seguro desejado.
  Exige duas condições independentes (`TRADING_MODE=real` + `REAL_TRADING_UNLOCKED=true`) para
  que um typo em uma variável de ambiente jamais habilite conta real.
- API/workers ficam fora de container: o conector MT5 exige terminal nativo no mesmo host.

[2026-08-04] História 2 — Modelos + migrations
- Append-only do audit_log ficou como trigger no Postgres (BEFORE UPDATE OR DELETE por linha
  + BEFORE TRUNCATE por statement). TRUNCATE precisa de trigger próprio: não dispara o de linha.
- Dois níveis de teste de banco: SQLite in-memory (constraints portáveis, roda em qualquer
  máquina) e Postgres via Alembic (trigger, enum nativo, JSONB) sob o marker `integration`.
- SQLite ignora FK por default -> listener com PRAGMA foreign_keys=ON no conftest, senão os
  testes de FK passariam de mentira.
- SQLite só autoincrementa INTEGER PRIMARY KEY: audit_log.id usa
  BigInteger().with_variant(Integer(), "sqlite").
- Enum `direction` aparece em signals e outcomes; na migration os tipos são criados uma vez com
  postgresql.ENUM(create_type=False) + .create(bind, checkfirst=True), senão o segundo
  create_table falha com "type already exists".
- pg_engine usa connect_timeout=3: sem Postgres de pé o skip precisa ser em segundos.
- stop_loss NOT NULL no banco: a regra "SL obrigatório" vale mesmo se o risk manager for contornado.

## [2026-08-05] — Infra: Docker disponível
- **Gotcha que custou caro:** com Docker Desktop no Windows, `@localhost:5432` trava a conexão
  para sempre (sem timeout). O proxy anuncia `[::]:5432` mas não completa o handshake em IPv6.
  Sintoma: `alembic upgrade head` e os testes `integration` penduram sem nenhuma conexão
  aparecendo em `pg_stat_activity`. Troca para `127.0.0.1` resolve. Aplicado em config.py,
  .env.example, conftest.py e ci.yml.
- **Gotcha de encoding:** `Get-Content -Raw` no PowerShell 5.1 lê arquivo UTF-8 sem BOM como ANSI.
  Reescrever depois disso duplo-encoda os acentos. Use
  `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)` e `WriteAllText` com
  `UTF8Encoding($false)`. Para desfazer um duplo-encode já gravado, reinterprete via cp1252 (1252),
  não latin1 — latin1 quebra travessão e aspas curvas.
- Com Postgres de pé a suíte roda inteira: 83 testes, zero skip, coverage 93%.

## [2026-08-05] - Historia 6: Sentiment analyzer
- backend/analysis/sentiment_analyzer.py (SentimentScore, FinBertBackend, TextBlobBackend,
  load_backend, cache Redis, SentimentAnalyzer), backend/tests/test_sentiment_analyzer.py,
  `transformers.*` adicionado aos overrides de mypy no pyproject.
- **Aprendizados:**
  - Mesma forma do MT5Terminal para dependencia pesada: Protocol na assinatura + import dentro
    de `_load_finbert_pipeline` / `_load_textblob`. O teste faz monkeypatch do loader, entao o CI
    nunca baixa o modelo de 400MB nem exige o extra `nlp` instalado.
  - O clamp mora no `__post_init__` do SentimentScore, nao no chamador. Assim a faixa [-1,1] vale
    tambem para o que volta do cache - entrada adulterada no Redis nao vira score fora de faixa.
  - Chave de cache = `sentiment:v1:<engine>:<sha256 do texto normalizado>`. O engine no meio evita
    servir score do FinBERT para uma sessao rodando TextBlob; a normalizacao de espacos faz a
    mesma noticia, formatada diferente por fonte, cair na mesma entrada.
  - Cache e best-effort (padrao dos coletores, nao do MT5): excecao do Redis vira warning e o
    modelo recalcula. Cache e otimizacao; nao pode derrubar analise.
  - Confianca do FinBERT = probabilidade da classe vencedora, inclusive para `neutral` (mede
    quanta certeza ha de que nao ha direcao). No TextBlob nao existe probabilidade: usei
    |polarity|, unica medida de conviccao disponivel.
  - Rotulo desconhecido, texto vazio e cache corrompido devolvem `neutral()` = score 0 com
    confianca 0. Nunca um score inventado - o fusion pondera pela confianca, entao o sinal
    simplesmente nao pesa. Nao conflita com "sem mocks em producao": o que nao pode ser
    fabricado e preco.
  - RUF100 do ruff pega `# noqa: BLE001` como noqa inutil, porque BLE nao esta no select. E
    RUF002 barra `x` unicode (MULTIPLICATION SIGN) em docstring - acento comum passa, simbolo
    matematico nao.
  - Teste `integration` que grava no Redis precisa de chave unica por execucao (uuid4 no texto).
    Com chave fixa + TTL de 30s, a segunda rodada da suite le a entrada da primeira e a asserção
    "modelo chamado uma vez" vira falso positivo.
  - 170 testes, coverage 94% (97% no modulo novo). As unicas linhas descobertas sao os imports
    reais de transformers/textblob, ausentes nesta maquina e no CI.

## [2026-08-05] - Historia 7: Technical analyzer
- backend/analysis/technical_analyzer.py (IndicatorSnapshot, TechnicalScore, compute_indicators,
  TechnicalAnalyzer), backend/tests/test_technical_analyzer.py, pandas-stubs no extra dev.
- **Aprendizados:**
  - Indicadores 100% da lib `ta` (RSIIndicator, MACD, BollingerBands, AverageTrueRange). O modulo
    so normaliza e combina - nao ha formula de indicador escrita aqui.
  - Convencao de sinal unica: positivo = vies de compra. RSI e Bollinger entram como reversao a
    media; MACD entra como momento de tendencia. ATR nao e direcional: serve de escala.
  - MACD normalizado por ATR (histograma / atr). Sem isso o componente fica em unidade de preco e
    um par volatil domina o score so por oscilar mais.
  - confianca = concordancia x intensidade: abs(soma) / soma(abs) vezes a media das magnitudes.
    Componentes que se anulam derrubam a confianca mesmo com score alto. Score diz direcao,
    confianca diz se ela foi sustentada por mais de um indicador.
  - Pesos ficaram fixos e iguais de proposito. O peso versionado e da historia 8 (signal_fusion);
    versionar peso em dois lugares seria duas fontes de verdade.
  - Indicador em aquecimento (NaN) devolve neutral(), nao zero - mesma regra do sentiment. Mas
    coluna OHLC ausente levanta ValueError: schema errado e bug de programacao, nao ausencia de
    dado de mercado. Sao caminhos distintos.
  - Serie OHLC constante deixa o RSI indefinido (sem ganho e sem perda -> NaN). A fixture "plana"
    exercita o caminho de NaN, nao o caminho feliz.
  - mypy strict exigiu pandas-stubs (import-untyped). Com os stubs, `pd.isna(float)` e tipado como
    sempre falso e o warn_unreachable acusa o corpo do if -> usar math.isnan para escalar.
  - Cai no RUF002 de novo (simbolo x unicode em docstring). O gotcha ja estava no AGENTS.md.
  - 189 testes, coverage global 95%, 100% no modulo novo.

  - `signals.strategy` (fonte para performance/outcomes) e `trades.strategy` (fonte para cooldown)
    são deliberadamente duplicados — não é a mesma coisa vista de dois lugares. Testes que chamam
    `_pode_abrir_posicao`/`_executar` direto (sem passar por `_process_symbol`/`Signal`) só
    continuam funcionando porque `Trade.strategy` tem default Python `"technical"` e não depende de
    um `Signal` existir; se a decisão fosse via JOIN a `Signal.strategy`, todo teste que cria
    `Trade(signal_id=None)` direto (comum em `test_runner_limites.py`) quebraria silenciosamente ao
    tratar o trade como "sem estratégia registrada" em vez de "technical".
  - `_registrar_bloqueio` (história 36) ganhou `strategy` na chave de dedupe. Sem isso, duas
    estratégias bloqueando pelo mesmo motivo no mesmo símbolo no mesmo ciclo colapsavam num só
    evento de audit log — a segunda parecia repetição da primeira, mas era um bloqueio novo de uma
    fonte diferente.
  - ATR e sentimento continuam lidos **uma vez por símbolo**, fora do loop de estratégias — são
    dado de mercado/contexto, não opinião de estratégia. Só `direction`/`confidence`/`components`
    vêm de cada `Strategy.evaluate()`; o stop (ATR-based) e a fusão com sentimento são
    infraestrutura compartilhada.
  - `Signal.inputs["indicators"]` (o snapshot bruto de RSI/MACD/etc.) saiu do payload — não fazia
    sentido genérico entre estratégias com componentes próprios (histórias 40-42 não terão
    `IndicatorSnapshot`). Virou `Signal.inputs["components"]` (o dict de scores por indicador que
    a estratégia já expõe via `StrategySignal.components`). Nenhum código de produção lia a chave
    antiga — só um teste, atualizado junto.
  - `StrategySignal` carrega `score: float` além de `direction`/`confidence`/`components` (não
    pedido explicitamente pela AC, mas necessário): é o que permite ao runner reconstruir um
    `TechnicalScore`-like e reaproveitar `fuse_signals` sem duplicar a aritmética de combinação
    peso-técnico × peso-sentimento para cada estratégia nova.
  - `backend/execution/order_manager.py` está em 73% de cobertura isolada (já estava em 72% antes
    desta história — não é regressão introduzida aqui, é lacuna pré-existente nos ramos de erro do
    MT5/IntegrityError). Cobertura global da suíte seguiu ≥80% (93,5%); não mexi nisso por não ser
    escopo desta história.

## [2026-08-06] — História 40: Estratégia BBRSI
- `BBRSIStrategy` em `backend/analysis/strategy.py`: porta fiel de `BBRSI.mq5`
  (github.com/geraked/metatrader5/blob/master/Experts/BBRSI.mq5), Bollinger(500, 2.0) + RSI(7),
  reversão à média. `evaluate` verifica as seis condições de compra (RSI[-2]<30 e fechamento
  abaixo da banda inferior; RSI[-1] volta acima de 30, fechamento volta acima da banda inferior,
  RSI[-1] ainda <50 e fechamento ainda abaixo da média) e o espelho de venda (70/50/banda
  superior). Registrada como `"bbrsi"` em `STRATEGY_REGISTRY`.
- `StrategySignal` ganhou o campo `stop_loss: float | None = None`. BBRSI o preenche com a fórmula
  da fonte (`BB_L - SLCoef*(BB_M-BB_L)` na compra, espelho na venda, `SLCoef=0.9` default);
  `TechnicalStrategy` deixa `None` e mantém o comportamento antigo.
- `backend/execution/runner.py`: `_executar` ganhou o parâmetro `stop_loss_override`. Quando
  presente (vindo de `resultado.stop_loss` via `_avaliar_estrategia`), o stop da estratégia
  substitui o ATR global — `distancia_sl` vira `abs(entry-stop)` e o take profit continua no mesmo
  RR configurado, agora aplicado sobre essa distância. O guard `atr<=0` só bloqueia quando NÃO há
  override (uma estratégia com stop próprio não depende de volatilidade medida).
- Arquivos alterados: `backend/analysis/strategy.py`, `backend/execution/runner.py`,
  `backend/tests/test_strategy.py` (9 testes novos: série curta com os defaults reais BB(500),
  série curta com período configurado, compra, venda, neutro/HOLD, nome, registro,
  `build_enabled_strategies`), `backend/tests/test_runner.py` (3 testes novos: override substitui
  ATR mesmo com `atr=0.0`, override igual à entrada bloqueia por `stop_invalido`, `_process_symbol`
  ponta-a-ponta com uma `_StubStrategy` que carrega `stop_loss`), `prd.json`.
- **Aprendizados para as próximas iterações:**
  - Fonte real (`WebFetch` no raw do GitHub) em vez de só a descrição do PRD: o coeficiente do SL
    (`SLCoef=0.9`) e a convenção de índice de barra (0=barra em formação, 1=último candle fechado,
    2=penúltimo — o MQL5 usa `ArraySetAsSeries`) só apareceram lendo o `.mq5` de verdade. A
    descrição do PRD já vinha extraída da fonte, mas não citava o coeficiente.
  - Ver os quatro padrões novos no topo do arquivo (Codebase Patterns): estratégia de padrão
    gráfico é sinal binário; `stop_loss_override` no runner; `STRATEGY_REGISTRY` crescendo quebra
    teste que usa nome de estratégia futura como exemplo de "desconhecida"; candle mínimo por
    estratégia é independente do `CANDLES_POR_CICLO` do runner.
  - Fixtures de teste usaram BB(20)/RSI(3) em vez dos defaults reais BB(500)/RSI(7) — a própria AC
    de "período configurável" existe para isso. Encontrar uma série de 22 candles que dispara as
    seis condições exatas exigiu busca por força bruta (`ta` real rodado num script, não os
    indicadores reimplementados à mão) — Bollinger de janela curta é sensível: um candle extremo
    dentro da própria janela infla o desvio padrão junto, então "furar a banda" com só 1-2 barras
    de amplitude não funciona; precisa de uma linha de base de baixa volatilidade (sawtooth) antes
    do movimento brusco para o desvio padrão ficar pequeno o bastante.
  - `ruff format` reflui automaticamente linha `E501` de dict/tuple longos — rodar `ruff format`
    antes de `ruff check` nos arquivos tocados evita ping-pong manual de quebra de linha.
  - Reescrever `prd.json` inteiro via `json.dump` troca CRLF por LF e explode o diff em ~580
    linhas por causa da mudança de terminador, mesmo alterando 1 campo. O arquivo é CRLF — usar
    `Edit` (troca de string pontual) para marcar `"passes": true`, nunca reserializar o JSON
    inteiro.
