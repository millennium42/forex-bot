## Codebase Patterns
- Gerenciador de pacotes e `uv`. Todo comando roda por `uv run`. Nunca pip/poetry.
- Config so em `backend/config.py`. Nenhum modulo le `os.environ` direto.
- Invariante de dados vive no schema (NOT NULL, UNIQUE, CHECK, trigger), nao na aplicacao.
- Teste de banco em dois niveis: SQLite in-memory (fixture `session`) e Postgres via Alembic
  (fixture `pg_engine`, marker `integration`, pula em 3s se o banco nao responde).
- `from __future__ import annotations` no topo de todo modulo (mypy strict + Python 3.12).
- Docstrings e comentarios em portugues; identificadores em ingles.
- Migrations sao aditivas. Nunca editar revisao ja aplicada.
- Scripts do Ralph leem prd.json via Python, nao jq (jq nao esta instalado nesta maquina).

## Aprendizados (append-only — nunca editar linha anterior)

[2026-08-04] História 1 — Scaffold
- Ambiente de dev: Windows 10, sem Docker, `python` do PATH é o stub da Windows Store.
  Python 3.12.13 instalado via `uv python install 3.12`. Todo comando roda por `uv run`.
- `MetaTrader5` é win32-only. Resolvido com marker `sys_platform == 'win32'` no pyproject,
  para o CI em Ubuntu não quebrar na resolução de dependências.
- `transformers`+`torch` movidos para o extra `nlp`: ~2GB não pertence ao caminho crítico do CI.
- O fail-closed do trading mode ficou como propriedade derivada (`effective_trading_mode`), não
  como validador do campo. Motivo: um validador que rejeita valor inválido derruba o processo no
  boot; a propriedade derivada degrada para demo, que é o comportamento seguro desejado.
  Exige duas condições independentes (`TRADING_MODE=real` + `REAL_TRADING_UNLOCKED=true`) para
  que um typo em uma variável de ambiente jamais habilite conta real.
- API/workers ficam fora de container: o conector MT5 exige terminal nativo no mesmo host.

[2026-08-04] História 2 — Modelos + migrations
- Append-only do audit_log ficou como trigger no Postgres (BEFORE UPDATE OR DELETE por linha
  + BEFORE TRUNCATE por statement). TRUNCATE precisa de trigger próprio: não dispara o de linha.
- Dois níveis de teste de banco: SQLite in-memory (constraints portáveis, roda em qualquer
  máquina) e Postgres via Alembic (trigger, enum nativo, JSONB) sob o marker `integration`.
- SQLite ignora FK por default -> listener com PRAGMA foreign_keys=ON no conftest, senão os
  testes de FK passariam de mentira.
- SQLite só autoincrementa INTEGER PRIMARY KEY: audit_log.id usa
  BigInteger().with_variant(Integer(), "sqlite").
- Enum `direction` aparece em signals e outcomes; na migration os tipos são criados uma vez com
  postgresql.ENUM(create_type=False) + .create(bind, checkfirst=True), senão o segundo
  create_table falha com "type already exists".
- pg_engine usa connect_timeout=3: sem Postgres de pé o skip precisa ser em segundos.
- stop_loss NOT NULL no banco: a regra "SL obrigatório" vale mesmo se o risk manager for contornado.

  - get_ticks falha inteira se um simbolo falhar - retorno parcial esconderia do pipeline que a
    visao de mercado esta incompleta.
  - mypy strict: `import MetaTrader5` sem stub retorna Any; use cast(MT5Terminal, MetaTrader5).

## [2026-08-05] — Infra: Docker disponível
- **Gotcha que custou caro:** com Docker Desktop no Windows, `@localhost:5432` trava a conexão
  para sempre (sem timeout). O proxy anuncia `[::]:5432` mas não completa o handshake em IPv6.
  Sintoma: `alembic upgrade head` e os testes `integration` penduram sem nenhuma conexão
  aparecendo em `pg_stat_activity`. Troca para `127.0.0.1` resolve. Aplicado em config.py,
  .env.example, conftest.py e ci.yml.
- **Gotcha de encoding:** `Get-Content -Raw` no PowerShell 5.1 lê arquivo UTF-8 sem BOM como ANSI.
  Reescrever depois disso duplo-encoda os acentos. Use
  `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)` e `WriteAllText` com
  `UTF8Encoding($false)`. Para desfazer um duplo-encode já gravado, reinterprete via cp1252 (1252),
  não latin1 — latin1 quebra travessão e aspas curvas.
- Com Postgres de pé a suíte roda inteira: 83 testes, zero skip, coverage 93%.

## [2026-08-05] - Historia 5: Twitter collector
- backend/collection/twitter_collector.py (filtered stream v2), backend/collection/documents.py
  (store_items compartilhado, extraido do news_collector), task collection.collect_twitter em
  backend/collection/tasks.py, backend/tests/test_twitter_collector.py, +3 testes em
  test_celery_app.py.
- **Aprendizados:**
  - store_items saiu do news_collector para documents.py e passou a aceitar o Protocol
    CollectedItem (.dedupe_hash + .to_document()). News e Twitter compartilham tabela e
    idempotencia; duplicar o insert com savepoint seria duas fontes de verdade para o dedupe.
    news_collector reexporta store_items via __all__, entao a API publica dele nao mudou.
  - Dedupe do tweet e sha256("twitter:<id>"). O prefixo separa o espaco de hashes do usado pelas
    noticias: id de tweet e URL dividem a mesma coluna unica documents.dedupe_hash.
  - Regras do filtered stream sao globais por conta, nao por conexao. sync_rules apaga o que
    esta cadastrado antes de adicionar; sem isso um filtro antigo continuaria injetando tweets
    fora do escopo configurado.
  - Stream e infinito: a task consome uma janela (DEFAULT_STREAM_LIMIT=200) e fecha. Sem teto a
    task nunca comitaria. Reexecutar e seguro pelo dedupe no banco.
  - Linha em branco no NDJSON e keep-alive do servidor, nao erro. Linha que nao parseia e pulada
    com warning - objeto malformado nao pode encerrar a coleta.
  - -is:retweet na regra: retweet repete o texto do original e enviesaria o sentimento por
    contagem.
  - httpx.MockTransport cobre client.stream(): Response(200, content=bytes) ja alimenta
    iter_lines(). Nao precisa de servidor de teste.
  - Task Celery nao tem atributo .queue. A fila real se verifica com
    app.amqp.router.route({}, nome)["queue"].name - nao abre conexao com o broker.
  - Token so vive no header do client (build_client). Nenhum log recebe credencial.

## [2026-08-05] - Historia 6: Sentiment analyzer
- backend/analysis/sentiment_analyzer.py (SentimentScore, FinBertBackend, TextBlobBackend,
  load_backend, cache Redis, SentimentAnalyzer), backend/tests/test_sentiment_analyzer.py,
  `transformers.*` adicionado aos overrides de mypy no pyproject.
- **Aprendizados:**
  - Mesma forma do MT5Terminal para dependencia pesada: Protocol na assinatura + import dentro
    de `_load_finbert_pipeline` / `_load_textblob`. O teste faz monkeypatch do loader, entao o CI
    nunca baixa o modelo de 400MB nem exige o extra `nlp` instalado.
  - O clamp mora no `__post_init__` do SentimentScore, nao no chamador. Assim a faixa [-1,1] vale
    tambem para o que volta do cache - entrada adulterada no Redis nao vira score fora de faixa.
  - Chave de cache = `sentiment:v1:<engine>:<sha256 do texto normalizado>`. O engine no meio evita
    servir score do FinBERT para uma sessao rodando TextBlob; a normalizacao de espacos faz a
    mesma noticia, formatada diferente por fonte, cair na mesma entrada.
  - Cache e best-effort (padrao dos coletores, nao do MT5): excecao do Redis vira warning e o
    modelo recalcula. Cache e otimizacao; nao pode derrubar analise.
  - Confianca do FinBERT = probabilidade da classe vencedora, inclusive para `neutral` (mede
    quanta certeza ha de que nao ha direcao). No TextBlob nao existe probabilidade: usei
    |polarity|, unica medida de conviccao disponivel.
  - Rotulo desconhecido, texto vazio e cache corrompido devolvem `neutral()` = score 0 com
    confianca 0. Nunca um score inventado - o fusion pondera pela confianca, entao o sinal
    simplesmente nao pesa. Nao conflita com "sem mocks em producao": o que nao pode ser
    fabricado e preco.
  - RUF100 do ruff pega `# noqa: BLE001` como noqa inutil, porque BLE nao esta no select. E
    RUF002 barra `x` unicode (MULTIPLICATION SIGN) em docstring - acento comum passa, simbolo
    matematico nao.
  - Teste `integration` que grava no Redis precisa de chave unica por execucao (uuid4 no texto).
    Com chave fixa + TTL de 30s, a segunda rodada da suite le a entrada da primeira e a asserção
    "modelo chamado uma vez" vira falso positivo.
  - 170 testes, coverage 94% (97% no modulo novo). As unicas linhas descobertas sao os imports
    reais de transformers/textblob, ausentes nesta maquina e no CI.

## [2026-08-05] - Historia 7: Technical analyzer
- backend/analysis/technical_analyzer.py (IndicatorSnapshot, TechnicalScore, compute_indicators,
  TechnicalAnalyzer), backend/tests/test_technical_analyzer.py, pandas-stubs no extra dev.
- **Aprendizados:**
  - Indicadores 100% da lib `ta` (RSIIndicator, MACD, BollingerBands, AverageTrueRange). O modulo
    so normaliza e combina - nao ha formula de indicador escrita aqui.
  - Convencao de sinal unica: positivo = vies de compra. RSI e Bollinger entram como reversao a
    media; MACD entra como momento de tendencia. ATR nao e direcional: serve de escala.
  - MACD normalizado por ATR (histograma / atr). Sem isso o componente fica em unidade de preco e
    um par volatil domina o score so por oscilar mais.
  - confianca = concordancia x intensidade: abs(soma) / soma(abs) vezes a media das magnitudes.
    Componentes que se anulam derrubam a confianca mesmo com score alto. Score diz direcao,
    confianca diz se ela foi sustentada por mais de um indicador.
  - Pesos ficaram fixos e iguais de proposito. O peso versionado e da historia 8 (signal_fusion);
    versionar peso em dois lugares seria duas fontes de verdade.
  - Indicador em aquecimento (NaN) devolve neutral(), nao zero - mesma regra do sentiment. Mas
    coluna OHLC ausente levanta ValueError: schema errado e bug de programacao, nao ausencia de
    dado de mercado. Sao caminhos distintos.
  - Serie OHLC constante deixa o RSI indefinido (sem ganho e sem perda -> NaN). A fixture "plana"
    exercita o caminho de NaN, nao o caminho feliz.
  - mypy strict exigiu pandas-stubs (import-untyped). Com os stubs, `pd.isna(float)` e tipado como
    sempre falso e o warn_unreachable acusa o corpo do if -> usar math.isnan para escalar.
  - Cai no RUF002 de novo (simbolo x unicode em docstring). O gotcha ja estava no AGENTS.md.
  - 189 testes, coverage global 95%, 100% no modulo novo.

## [2026-08-05] - Historia 8: Signal fusion
- backend/analysis/signal_fusion.py (FusionWeights, FusedSignal, fuse_signals), backend/tests/test_signal_fusion.py
- **Aprendizados:**
  - A confiança da fusão penaliza dois cenários explicitamente: informações ausentes/nulas (ex: sentimento offline) e componentes discordantes (técnica compra, sentimento vende).
  - Score direcional é preservado independentemente da confiança. A decisão categórica (BUY, SELL, HOLD) obedece a um threshold de convicção.
  - FusedSignal grava o `weight_version` para a mesma decisão poder ser reproduzida ou testada contra novos pesos no otimizador (história 13).
  - O type hint do mypy pra `indicators=None` não exigiu `# type: ignore` no strict mode.

## [2026-08-05] - Historia 10: Order manager
- backend/execution/order_manager.py e backend/tests/test_order_manager.py
- **Aprendizados:**
  - Idempotência resolvida no banco antes do broker: o lock otimista via `client_request_id` (com `IntegrityError` rollback) previne ordens duplicadas, enquanto o DB atua como fonte de verdade.
