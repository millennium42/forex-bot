## Aprendizados (append-only — nunca editar linha anterior)

[2026-08-04] História 1 — Scaffold
- Ambiente de dev: Windows 10, sem Docker, `python` do PATH é o stub da Windows Store.
  Python 3.12.13 instalado via `uv python install 3.12`. Todo comando roda por `uv run`.
- `MetaTrader5` é win32-only. Resolvido com marker `sys_platform == 'win32'` no pyproject,
  para o CI em Ubuntu não quebrar na resolução de dependências.
- `transformers`+`torch` movidos para o extra `nlp`: ~2GB não pertence ao caminho crítico do CI.
- O fail-closed do trading mode ficou como propriedade derivada (`effective_trading_mode`), não
  como validador do campo. Motivo: um validador que rejeita valor inválido derruba o processo no
  boot; a propriedade derivada degrada para demo, que é o comportamento seguro desejado.
  Exige duas condições independentes (`TRADING_MODE=real` + `REAL_TRADING_UNLOCKED=true`) para
  que um typo em uma variável de ambiente jamais habilite conta real.
- API/workers ficam fora de container: o conector MT5 exige terminal nativo no mesmo host.

[2026-08-04] História 2 — Modelos + migrations
- Append-only do audit_log ficou como trigger no Postgres (BEFORE UPDATE OR DELETE por linha
  + BEFORE TRUNCATE por statement). TRUNCATE precisa de trigger próprio: não dispara o de linha.
- Dois níveis de teste de banco: SQLite in-memory (constraints portáveis, roda em qualquer
  máquina) e Postgres via Alembic (trigger, enum nativo, JSONB) sob o marker `integration`.
- SQLite ignora FK por default -> listener com PRAGMA foreign_keys=ON no conftest, senão os
  testes de FK passariam de mentira.
- SQLite só autoincrementa INTEGER PRIMARY KEY: audit_log.id usa
  BigInteger().with_variant(Integer(), "sqlite").
- Enum `direction` aparece em signals e outcomes; na migration os tipos são criados uma vez com
  postgresql.ENUM(create_type=False) + .create(bind, checkfirst=True), senão o segundo
  create_table falha com "type already exists".
- pg_engine usa connect_timeout=3: sem Postgres de pé o skip precisa ser em segundos.
- stop_loss NOT NULL no banco: a regra "SL obrigatório" vale mesmo se o risk manager for contornado.
